# 0022. 懂我引擎：乘法四因子取代顺序式排除堆叠

日期：2026-07-27
状态：已接受（redesign-brief §四§五定案的执行细则）

## 背景

v2 的选择内核是三层顺序堆叠：Cooldown 硬排除 → Recency window 权重减半 →
leastShown 最少展示过滤，外加菜名二字词相似度的 Discovery 启发式。用户判定其
不可解释、不可调，且「每次减半」与「最少展示」两条规则互相打架。redesign-brief
判处该结构死刑，域语义（按次数反重复、Discovery 显式标注、待评分拦截、加权随机、
可解释启发式家法）保留。

## 决定

### 评分模型

对池中每道菜，在每次揭示时计算：

```
Score(菜, 此刻) = 喜爱 × 新鲜感 × 场合 × 本顿否决
```

乘完对全池做加权随机抽样。四因子定义：

| 因子 | 定义 |
|---|---|
| 喜爱 | 档位乘数：人上人 0.5、顶尖 1.0、夯 2.0（夯:人上人 = 4:1）|
| 新鲜感 | d = 距该菜上次被接受之后的吃饭记录数：d≤1→0（冷却）；2→0.35；3→0.6；4→0.8；5→0.9；6–11→1.0；≥12→1.2（久别重逢）；从未吃过→1.0 |
| 场合 | 按客户端上报的本机小时：早餐类（breakfast 桶）5–10 点为 1.0、其余时段 0.15；condiment/drink/dessert/semi-finished 四桶恒 0（永不直接揭示）；其余桶恒 1.0 |
| 本顿否决 | 本 Meal 已展示过 → 0（取代 leastShown）|

### 全零逐层放宽

池非空却全零时按「新鲜感 → 场合 → 本顿否决」逐层置 1 重算，每层在 reason
里说人话（如「都在冷却，破例放行」）。永零类（场合恒 0 的四桶）不因放宽复活——
放宽只解除时段惩罚，不解除品类禁令。放宽到底仍全零（池里只有永零类）视同空池：
宁可说没得选，也不把酱料端上桌。

### 自动降档

brief 原文「最近 5 次登台 ≥4 次被换、0 次被接受」与「任何接受即清零计数」联立后
的等价形式：**per(账号,菜) 维护 pool 模式连换计数器，被换 +1，被接受清零，
计数达到 4 即降一档并清零**（接受清零使窗口内不可能同时有接受与 4 次被换；放弃
的 Meal 里站着的那道菜不计）。地板人上人，永不自动移出；只降不升；降档立即反映
在池子页徽标，零打扰。

### Reroll budget 与三出口

每 Meal 3 次 Reroll，服务端结算，State 携带余量。越限返回
`reroll_budget_exhausted`。用尽后三出口：

1. 接受当前揭示（原路径）；
2. 亲自点一道：仅此刻解锁（未耗尽时返回 `hand_pick_locked`），从池中手选一道
   成为本顿结局，落 `hand_pick` 模式的 Decision 与正常吃饭记录；
3. 放弃本顿：Meal → abandoned，无吃饭记录，不进冷却；其 Reroll 仍计入探索压力
   （修正案：压力窗口从「最近 3 个已接受 Meal」改为「最近 3 个已了结——接受或
   放弃——的 Meal」）。

### 探索臂

三信号（池小、冷却后可选少——新鲜感>0 的池菜数、近窗 Reroll 多）不再是
「满 2 即必探索」的开关，而是折算概率：命中 s 个信号 → 本次揭示以 s/4 概率走
Discovery（0.25/0.5/0.75），每顿上限与显式标注照旧。候选权重 =
口味画像相似度 × 参照菜喜爱档乘数 × 候选自身场合 × 候选自身新鲜感。

### 口味画像相似度（取代菜名二字词碰撞）

导入期对每道菜确定性萃取 Taste profile：主料（原料清单+菜名 过主料词典）、
味型（菜名+描述段 过味型词典）、工艺（菜名[+步骤，视词条标注] 过工艺词典）、
品类（目录桶）。三部词典是仓库数据（`internal/catalog/dictionaries/`）。

```
相似度(候选, 参照) = 5×|主料交集| + 4×|味型交集| + 2×[工艺同] + 1×[品类同]
```

对全池参照取 `max(相似度 × 参照喜爱档乘数)`；探索理由行由命中维度生成
（「跟你爱的口水鸡一样是鸡肉，试试新的」）。

### 理由管道

`Decision.reason` 从 Discovery 专属升格为每次揭示必有。每个起作用的因子吐一句
人话，组句优先级：放宽说明 > 探索命中维度 > 久别重逢 > 场合加成 > 喜爱档位
（兜底「你的夯/顶尖/人上人」）。短句、全中文、零系统腔。

### 档位正名与存储

评分五档：1 拉完了、2 NPC、3 人上人、4 顶尖、5 夯。≤2 → 拒绝标记（可逆，重新
入池即撤销）；入池场景只开上三档。`candidate_pool.preference_weight`（连续浮点）
重建为 `tier INTEGER CHECK (tier IN (3,4,5))`，旧值回填：<0.85→3、<1.15→4、
其余→5（覆盖旧评分映射 0.7/1.0/1.3 与手工权重）。数字仍是内部实现，wire 与 UI
只说档位语言。

## 处决台账（勿复活）

`cooldownSize`/`cooldownSet` 阶梯沉默放宽、`halveRecentWeights`、
`leastShownDishes`、`nameBigrams` 及其相似度、顺序式三层堆叠、
`preference_weight` 连续浮点 wire 契约、Discovery 的「满信号必触发」开关语义。

## 后果

- 引擎成为纯函数包 `internal/engine`（无 DB），因子曲线可表驱动单测；
  `internal/meal` 只剩事务壳与记账。
- 反重复从「硬排除+减半」双轨并为一条新鲜感曲线，可解释且单调。
- 新增 wire：`reroll_budget_exhausted`、`hand_pick_locked`、abandon/hand-pick/
  eating-records 端点、`local_hour` 上报、State.rerolls_remaining、pool 端点
  tier 化。北极星「首揭接受率」可从 decisions 表直接计算，零埋点。
