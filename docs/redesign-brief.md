# What2Eat 全面重构规格（2026-07-27 拷问定案）

经一场完整 grilling 会话逐条决议的执行规格。领域词汇的正式定义一律以 `CONTEXT.md`
为准（本次已同步：Taste interview、Decision stage、Reroll budget、Meal abandonment、
Taste profile、Taste rating 档位、Preference weight 主权原则、Discovery 相似度语义）。

**状态：已立案，未动工。** 动工双门：

## 一、目标与北极星

- 病因判定：上一版整套视觉系统（背景/字体/卡片/按钮）显得廉价，无 Claude 式克制温和气质。
- 北极星（算法侧）：**首揭接受率**——揭示后 ≤1 次 Reroll 内被接受的比例；从 decisions 表直接可算，零埋点。
- 两条凌驾性设计约束：
  - **为第五十次设计**：揭示动效一拍内、可被连续 Reroll 打断；老用户主路径两击开饭（进站 → 开始这一顿 → 接受）；访谈永不拦路。
  - **状态与语气是高级感的另一半**：加载/错误/空/慢网络全部非理想态纳入设计；文案短句、笃定、全中文、零系统腔、零 emoji。

## 二、视觉与前端地基

- 设计主导：用户安装的设计技能；用户口味为终审。参照系 = claude.ai 真实界面
  （平坦暖纸底色、极少色数、衬线展示字、小而稳的按钮、几乎不可察觉的动效）+
  既有偏好（Lucide、零 emoji、衬线展示字、Awwwards 级完成度）。
- 组件库：**antd → shadcn/ui + Tailwind 全量迁移**（执行时立 ADR）。antd 时代的
  补丁（ConfigProvider autoInsertSpace、WeightControl 键盘去抖、LazyMotion 约束）随迁移全部作废。
- 旧三层契约**全部作废**：Playwright 规格零改动军规、`copy.ts` 锁定文案、标题层级政策。
  设计期用户的眼睛是唯一门；旅程定稿后重织新规格（见「八、交付分段」）。
- 文案全中文化：处决「创建 Account」「返回 Meal readiness」式中英混排；领域术语只活在代码与词表。
- PWA：manifest + 图标，可装到手机桌面。深色模式：token 按明暗双态设计，本轮只交付亮色。

## 三、旅程与界面

- **登录/注册**：Claude 形制单步表单（用户名+密码同屏），登录/注册底部链接互切；
  无 OAuth、无两步流；处决 antd 分段大 tabs。
- **注册后**：无弹窗。主界面 Decision stage 的空池态即欢迎引导（衬线大标题 + 主 CTA
  「开始口味访谈」+ 次 CTA 手工挑菜 + **经典起步包**：十余道国民家常菜一键入池，默认中档，
  十秒可体验首次揭示）。
- **主界面（日常）**：简洁紧凑单屏驾驶舱：wordmark、账号状态与登出、加菜双入口
  （访谈/手工）、轻历史入口、Decision stage 舞台位。
- **Decision stage 三态互斥**：空池引导 / 待评分拦截 / 就绪开饭。揭示**就地完成**
  （无路由跳转）：一拍期待 → 菜名衬线大字落定 → 理由行 + 信息小字（耗时·难度）→
  接受 / Reroll（显示余量）。接受后跳转菜谱页。文案用「这一顿」系，禁用「今日推荐」。
- **菜谱页**：全量引入 HowToCook 图片（成品+步骤），统一容器驯化画质；无图菜自然纯文字。
  图片只进菜谱页——主界面/揭示/池子列表零图片（图为信息，不为装饰）。
- **池子页**：情感刻度徽标（点开五档切换，入池场景只见上三档）；无滑杆无数字。
- **轻历史**：「最近吃过 / 最近爱吃」安静入口；支持可选、绝不拦路的补评分（需小幅后端）。

## 四、懂我引擎（后端算法推倒重建，执行时立 ADR）

结构推倒、域语义保留（按次数反重复、Discovery 显式标注、待评分拦截、加权随机、可解释启发式家法）。

**Score(菜, 此刻) = 喜爱 × 新鲜感 × 场合 × 本顿否决**，乘完加权抽样；全零按
「新鲜感→场合」逐层放宽且每层在 reason 里说人话（「都在冷却，破例放行」）。

| 因子 | 定义 |
|---|---|
| 喜爱 | 档位映射 人上人 0.5 / 顶尖 1.0 / 夯 2.0（4:1）；含自动降档 |
| 新鲜感 | 距上次接受的吃饭记录数：0–1→×0（=冷却）；2→0.35、3→0.6、4→0.8、5→0.9、≥6→1.0；≥12→×1.2「久别重逢」 |
| 场合 | 客户端上报本机小时；早餐类仅早晨满值、其他时段 ×0.15；酱料/饮品/甜品/半成品**永远 ×0**；对池子与 Discovery 两路径同时生效 |
| 本顿否决 | 本顿已展示过 → ×0（取代 leastShown） |

- **自动降档**（零打扰）：只看 `mode='pool'` 展示；某菜最近 5 次登台 ≥4 次被换、0 次被接受
  → 降一档；地板人上人，永不自动移出/拒绝；任何接受即清零计数；降档后计数归零；只降不升；
  池子页徽标即时反映，无任何打扰。
- **Reroll budget**：每顿 3 次，服务端结算（新增越限 wire 错误码）。用尽三出口：
  接受 / **亲自点一道**（仅此刻解锁，进池手选成为本顿结局，正常产生吃饭记录）/ **放弃本顿**
  （Meal → abandoned，无吃饭记录，不进冷却）。
- **语义修正案（已批）**：探索压力的 Reroll 信号窗口从「最近 3 个已接受 Meal」改为
  「最近 3 个已了结（接受或放弃）Meal」。
- **探索臂**：三信号语义不变，折算探索概率；候选按 相似度 × 参照喜爱 × 场合 × 新鲜感 抽样；
  每顿上限、显式标注、评分闭环照旧。
- **理由管道**：每个因子起作用时吐一句人话理由；`Decision.reason` 从 Discovery 专属升格为
  每次揭示必有（「你的夯」「有阵子没吃它了」「像你爱的口水鸡，试试新的」）。
- 评分档位正名：**1 拉完了、2 NPC、3 人上人、4 顶尖、5 夯**；≤2 → 拒绝标记（可逆，
  重新入池即撤销）；入池场景只开上三档。Recency 旧「每次减半」废除，由新鲜感曲线接管。
- **死刑名单**：顺序式硬排除+减半+最少展示三层堆叠、`leastShownDishes`、`halveRecentWeights`、
  冷却阶梯沉默放宽、菜名二字词相似度。

## 五、口味画像与导入富化

- 导入时萃取 **Taste profile**：主料（原料清单+菜名，过主料词典）、味型（菜名+描述段，
  过味型词典）、工艺（菜名+步骤，过工艺词典）、品类（现有目录）。三部词典进仓库当数据。
- 相似度 = 5×主料交 + 4×味型交 + 2×工艺同 + 1×品类同，× 参照菜喜爱档，对全池取最大；
  探索理由行由命中维度生成。
- 同次解析顺手收：图片引用（菜谱页用，后端静态挂载 CATALOG_DIR）、难度星、卡路里、耗时
  （揭示信息小字用）。
- 排查 `template` 目录桶是否被当真菜导入（潜在脏数据）。
- 点名否决：嵌入向量（词表禁令维持）、LLM 离线打标（导入保持确定性与离线可用）。

## 六、口味访谈（Taste interview）

- 常驻入口、永远携带池子上下文（已有菜+档位）；空池首访只是退化情形；不重复推荐已有菜。
- 提示词纪律（grilling 方法论移植）：一次只问一个问题、每问附推荐答案、先场景菜系后具体菜、
  对每道入池菜追问喜爱并当场落档（同一套五档语言，只开上三档）、所有菜名锚定 Catalog 校验。
- 模型升级：默认 `NIM_MODEL` 弃 llama-3.1-8b，候选含 GLM-5.1 等中文原生模型；执行时以真实
  访谈脚本实测 2–3 个候选定型号；`NIM_BASE_URL`/`NIM_MODEL` 覆盖机制保留（可指向智谱等
  OpenAI 兼容端点）。

   （至少：shadcn 迁移、懂我引擎、口味画像与 Reroll budget）。
